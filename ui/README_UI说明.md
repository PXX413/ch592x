## 4. 编码器事件表（文档 (六)）

| 事件 | 产生条件 | 列表页 | 非列表页 | 框架行为 |
|---|---|---|---|---|
| `UI_ENC_CLICK` | 按下 <0.5s，300ms 内没有第二击 | 确认选中项 | 当普通按键 | 交给页面 `on_key` |
| `UI_ENC_DOUBLE` | 300ms 内第二击 | - | - | **全局**：回上一级 |
| `UI_ENC_HOLD` | 按住 >=0.5s | - | 执行当前操作 | 交给页面 `on_key` |
| `UI_ENC_HOLD1` | 按住 >=1s | - | 键盘页进设置页 | 交给页面 `on_key` |
| `UI_ENC_HOLD3` | 按住 >=3s | - | - | **全局**：直接回主页面 |
| 旋转 CW/CCW | 编码器转一格 | 正转向下 / 反转向上 | 步进调节 | 交给页面 `on_key` |

**三档长按各只吐一次**（0.5s / 1s / 3s），页面只接自己关心的那一档：
键盘页只接 `HOLD1`（需求 (二).3 写的是"长按 1 秒进设置页"），
其它页面的"当前操作"接 `HOLD`；`HOLD3` 由框架全局处理。
吐过任何一档长按之后松手，都不会再补一个 `CLICK`。

`UI_PostKey()` 里全局规则**优先于**页面处理，所以页面不必自己处理双击/超长按。

**键盘页的单击**（需求 (六).2"非列表页当 3x3 之外的按键用"）：
`kbd_key()` 收到 `GKEY_ENC_CLICK` 后调 `UiKbd_PulseExtra()`，在当前通道上
发一次"回车（0x28）按下 + 50ms 后松开"的脉冲 —— USB 走 `usb_kbd_report`
的 `ENC_BTN` 槽位，BLE / 2.4G 直接进 6KRO 报文的键码槽位。
用途码可以用 `UiKbd_SetExtraUsage()` 换，传 0 就关掉。

## 5. 通信仲裁时序（文档 (二).1）

```
开机
 |
 +- (a) 判断 USB ---------- 0.5s --+ 有 USB -> 锁定 USB
 |                                  |
 +- (b) 广播 2.4G -- 1 秒内对码+心跳？--+ 是 -> 锁定 2.4G
 |                                    |
 +- (c) 广播 BLE -- 无限等 -----------+ 连上 -> 锁定 BLE

任一条通道掉线（USB 拔了 / 2.4G 心跳没了 / BLE 断了）-> 从 (a) 重新走一遍
```

**注意**：已经锁定的通道**不会**被新出现的通道抢走（避免打字时键盘突然换通道）。
只有当前通道掉线才会重新仲裁。

## 6. 报文与三通道

报文是标准 **8 字节 6KRO 引导报表**：

```
[0] modifiers   左右 Ctrl/Shift/Alt/Win
[1] 0           保留
[2..7] 最多 6 个 HID 用途码，不足补 0
```

| 通道 | 逐键喂 | 发送 | 现状 |
|---|---|---|---|
| USB | `UsbKbd_KeyEvent()` | `UsbKbd_SendReportNow()` | **已接真实模块** |
| BLE | `BT_HID_KeyEvent()` | `BT_HID_Flush()` | **已接真实模块** |
| 2.4G | 不需要（整帧发） | `Kb_BuildHid6()` 打包 → **`HALRF_Tx()`** | **已真发**；但主机轮询（`Kb_HostPoll()`）还没接到主循环 |

键值映射：`KEY_GetMapped(n)` 是 16 位——**高字节 = 修饰键位图，低字节 =
主键 HID 用途码**。`ui_kbd.c` 里 `UiKbd_UsageOf()` 取低字节进键数组、
`UiKbd_ModsOf()` 取高字节进第 0 字节；低字节是 `0xE0~0xE7` 时转成对应的
修饰位（所以"单独一个 Ctrl 键"也能用）。USB 通道还会把这套映射同步给
`usb_kbd_report` 自己的键值表（`ui_kbd_ch.c` 的 `ch_usb_sync_map()`），
否则 USB 报表层永远按默认的 `K1~K9 = 数字 1~9` 发。
切换通道时会把当前按键状态**重喂一遍**给新通道，同时清掉旧通道的状态
（否则切回去会出幻影按键）。

## 7. 数据 Flash 分区（别撞车）

| 偏移 | 用途 |
|---|---|
| `0x0000 ~ 0x00FF` | `game_score`（最高分 + 难度/音效） |
| `0x0100` / `0x0200` | `rf_cfg`（2.4G 遥控配置，A/B 双 Bank） |
| **`0x0300`** | **`ui_store`**（led_on / led_bright / sleep_idx / map_group） |

`ui_store` 记录 16 字节：magic `0x5549` + ver + 4 个字段 + CRC16（覆盖 0..13）。

## 8. 键值映射组

`key_matrix.c` 里是 **4 组**（文档写 3 默认 + 2 自定义 = 5，实际做了 4）：

| 组 | 名字 | 内容 |

```
Memory region         Used Size  Region Size  %age Used
           FLASH:      209092 B       448 KB     45.58%
             RAM:       21540 B        26 KB     80.90%
   text    data     bss
 201656     800   14320
```

| 阶段 | FLASH | RAM |
|---|---|---|
| 键盘页接上之前（BLE 被 gc-sections 整块丢掉） | 36352 B (7.92%) | 6240 B (23.44%) |
| 只加 UI 页面代码、BLE 仍未引用 | 44396 B (9.68%) | 6240 B (23.44%) |
| BLE 真正接上之后 | 190788 B (41.59%) | 20352 B (76.44%) |
| 2.4G 发送接上 `HALRF_Tx` | 192648 B (41.99%) | 20664 B (77.61%) |
| 三个游戏共用状态池 | 192992 B (42.07%) | 20512 B (77.04%) |
| 2.4G 改成设备角色 + 遥控主机接入 | 196712 B (42.88%) | 20924 B (78.59%) |
| 遥控页真接 proto_rc（s_rch 常驻 bss） | 202456 B (44.13%) | 23732 B (89.14%) |
| 遥控主机改到堆上申请 | 202476 B (44.14%) | 21060 B (79.10%) |
| 游戏状态池也改成按需申请 | 202776 B (44.20%) | 20148 B (75.68%) |
| **BLE GATT 服务接上 + 2.4G/遥控射频互斥（当前）** | **209092 B (45.58%)** | **21540 B (80.90%)** |

**RAM 是现在的瓶颈**：只剩约 **6.1 KB**。
最大的单块是 WCH BLE 协议栈的 `MEM_BUF` = **6144 B**（BLE 内存池），
其次 `__sf` 312 B、`gBleLlPara` 296 B。

> 结论：FLASH 448 KB 还很有余量（42%），**RAM 77.6% 才是要盯的**。
>
> ### 临时内存现在都是"用时才申请"（RAM 89.14% -> 75.68%）
>
> 有两块较大的缓冲原本常驻 `.bss`，其实**只在某一种模式下**才用得上：
>
> | 缓冲 | 大小 | 什么时候才需要 |
> |---|---|---|
> | `rc_host_t` | 2680 B | 进遥控页 |
> | `game_pool_t` | 920 B | **真正进游戏以后**（选游戏列表还不用） |
>
> 现在统一走 `game_mem.c`：**进模式才 `GameMem_Acquire()`，退出就 `GameMem_Yield()`**。
>
> 关键约束：**同一时刻只允许一个所有者**。遥控和游戏永远不会同时用，
> 所以它们共用同一块堆内存也就不会打架——而且这条互斥是**有测试守着**的
> （`test_mem.c` 38 项：谁占着谁拿不到、还回去才能再拿、传别人的指针不会误放）。
>
> 堆来自系统自带的 `_sbrk`（`CH59x_sys.c`），范围 `_ebss` .. 栈底：
> 现在 **6472 B 可用**，而单块最大需求是 2680 B。
>
> 两条防线：
> * 申请失败返回 0 -> 遥控功能不可用、游戏进不去，但**都不崩**（调用方都判了）
> * `Main.c` 里有**编译期护栏**：`sizeof(rc_host_t)` 若大到堆放不下，直接编译不过
>
> `UIRC_DEV_MAX`（`ui_pages2.h`）仍可配：6 台 = 2.68KB / 3 台 = 1.34KB。
>
> **游戏状态池**：三个游戏各自开过实体池（雷霆 920 + 跑酷 ~90 + 2048 128 = 1108 B），
> 而同一时刻只跑一个。现在合成一块 `game_state.c` 的 union
> （实测 `s_pool` = **920 B**），**省下 188 B**（实际 RAM 净降 152 B，
> 差额是新增的现体代码。用法见 `game_state.h`：进游戏时取、退出时不再用旧指针。
>
> **`MEM_BUF` 已经到底了，调不小**：
> `bluetooth\CONFIG.h` 里 `BLE_MEMHEAP_SIZE` 定义为 `(1024*6)`，
> 而同一行的注释写明“最小 6K”。所以这 6144 B 是协议栈的下限，
> 不是可调参数。当前剩余 RAM 约 **5.8 KB**，是真正的硬预算。

## 12. BLE 键盘的 GATT 服务（补上的缺口）

### 12.1 原来缺什么

`bt_wch.c` 原先只做三件事：放 `MEM_BUF`、注册 GAP 回调、跑 `TMOS_SystemProcess()`。
**它从来没有注册过任何 GATT 服务**，所以主机连上来也看不到 HID 键盘 ——
`bt_hid.c` 把 8 字节报文算得再对也发不出去。这是 BLE 通道一直不能用的根因。

### 12.2 补了什么

从 `CH592EVT\EVT\EXAM\BLE\HID_Keyboard\Profile\` 按字节原样拷入 10 个官方
profile 文件（`hiddev` / `hidkbdservice` / `battservice` / `devinfoservice` /
`scanparamservice` 各自的 .c/.h）加 `hidkbd.h`，另写一层接线 `bt_gatt.c/.h`：

```
void BtGatt_Init(void);                        // 挂上四个 GATT 服务
void BtGatt_SetBatteryLevel(uint8_t percent);  // 喂电量
void BtGatt_ConnChange(uint16_t h, uint8_t t); // 连接/断开
bool BtGatt_SendReport(const uint8_t *rep8);   // 推 8 字节报文
```

`bt_wch.c` 里已补上：调用 `BtGatt_Init()`、配对/绑定参数
（`GAPBondMgr_*`）、从设备连接间隔（`GGS_PERI_CONN_PARAM_ATT`）、
以及扫描应答里的 **服务 UUID（HID 0x1812 + 电池 0x180F）** ——
主机在扫描阶段就靠这段判断这是键盘，不能省。

### 12.3 顺带修掉的"发不出去"

`ch_ble_send()` 原来调 `BT_HID_Flush()`，那里面走的是 `bt_port.c` 的
`BT_SendHid()`，而 `bt_port` 的后端指针要靠 `BT_Init()` 注册 ——
**本工程从头到尾没调过 `BT_Init()`**，所以 `s_be` 一直是 0，
`BT_SendHid()` 永远返回 false。现在改成直接把算好的报文交给
`bt_wch.c` 的 `BT_WCH_SendHid()`，`test_kbd_ch` 里有断言守着这一条。

## 13. 2.4G 键盘与遥控的射频互斥

### 13.1 为什么必须互斥

CH592 只有**一个** accessAddress。键盘模式在本机链路地址上等主机 POLL；
而 `proto_rc.c` 自己会调 `HALRF_SetLink()`：

* 枚举阶段 → `h->enum_addr`（固定 `0xAABBCCDD01`）
* 数据阶段 → `h->rc_addr`

两者共用同一颗射频、同一份 HAL 状态。同时跑的话，键盘的 `HALRF_RxWait()`
会等在遥控的地址上，永远收不到 POLL，双方互相覆盖地址。

### 13.2 怎么做的

新增 `UiKbdCh_SetRadioMode(bool keyboard_on)`：

* 进遥控页 → `false`：键盘撒手，清掉 2.4G 心跳
* 离开遥控页 → `true`：用 `RfCfg_KbLoad()` 取回配对信息，
  `HALRF_SetLink()` 把地址**还给键盘**，心跳清零重新判

`Main.c` 里用 `s_rc_active` 门控键盘的 `UiKbdCh_PollRf24()`，
保证同一时刻只有一方在用射频。`test_kbd_ch` 里有断言验证
"离开遥控后地址恢复成键盘前缀 0x71、且不是遥控枚举地址"。
