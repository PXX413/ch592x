## 二、怎么用

1. 把 `games\` 整个目录放进工程根目录（和 `hardware\` 同级）；
2. 工程里按 **F5 刷新**，新文件就会出现在工程树里并自动参与编译；
3. 把 `main_example.txt` 的内容复制进 `User\Main.c`（或直接用它替换该文件）。
   注意：**不能**让 `.txt` 参与编译，所以它的扩展名是 `txt`；
4. 编译、下载。

> `games\` 里所有 `.c` 都只依赖已经编译进工程的驱动文件，
> 唯一需要确认的是 `User\Main.c` 里不要再留原来的 `main()`。

## 三、操作

### 菜单
| 按键 | 作用 |
|------|------|
| 编码器旋转 / K4 K6 | 上下选游戏 |
| K5 或 编码器按键 | 开始选中的游戏 |
| K1 / K3 | 难度 - / + |
| K7 | 音效开关（设置会存进数据 Flash） |
| 成绩页 | 任意键回菜单 |

### 2048
| 按键 | 作用 |
|------|------|
| K5 / K8 / K4 / K6 | 上 / 下 / 左 / 右 |
| K7 | 撤销一步 |
| K9 | 回菜单 |
| 结束后 K5 或 编码器按键 | 重开一局 |

标准规则：同值合并（一次移动里每块只合并一次），每次有效移动生成 2（90%）或 4（10%）。
凑出 2048 会显示"胜利"，但可以继续玩到无路可走。

### 跑酷
| 按键 | 作用 |
|------|------|
| K5 | 跳（站在地上时） |
| 编码器按键 | 二段跳（空中一次） |
| K8（按住） | 滑铲（钻过悬空障碍） |
| K7 / K9 | 暂停 / 回菜单 |

三种障碍：矮的（跳过）、高的（要二段跳）、悬空的（滑铲）。分数 = 距离 / 10，速度 90 → 300 像素/秒。

### 雷霆战机
| 按键 | 作用 |
|------|------|
| K5（按住） | 战机向上飞 |
| K8（按住） | 战机向下飞 |
| K4（按住） | 连发，每 120ms 一发 |
| 编码器按键 | 放炸弹：清掉全场敌弹 + 全场敌机扣 3 血 + Boss 扣 10 血（一共 3 颗） |
| K7 | 暂停 / 继续 |
| K9 | 回菜单 |
| 标题页 / 结束后 K5 或 编码器按键 | 开始 / 重开 |

* 状态机：`BOOT（约 0.5s 标题）→ MENU → PLAYING ? PAUSED → GAMEOVER / WIN`
* 3 条命，被撞一次掉一条命 + 2 秒无敌（期间闪烁；开局也有 2 秒无敌）
* 4 种敌机：小飞机（1 血 100 分）、斜飞（1 血 150 分）、射击机（2 血 300 分，会还击）、
  高速机（1 血 200 分）；打掉第 3 波会出 **Boss**（50 血、边移动边打三向炮、5000 分），
  击落 Boss = 通关
* 难度曲线（和文档第十章一致）：

| 波次 | 时间 | 敌机速度 | 生成间隔 | 出现的敌机 |
|------|------|---------|---------|-----------|
| 1 | 0~30s | 1.0x | 1000ms | 小飞机 |
| 2 | 30~60s | 1.2x | 800ms | + 斜飞 |
| 3 | 60~90s | 1.5x | 600ms | + 射击机 + 高速机，**Boss 登场** |
| 4 | 90~120s | 1.8x | 500ms | 全部 |
| 5 | 120s+ | 2.0x | 400ms | 全部 |

> Boss 战期间普通敌机照出，但生成间隔放慢，免得屏幕上太挤。

## 四、难度与最高分

* 难度（简单 / 普通 / 困难）影响：跑酷的起步速度、雷霆战机的敌机与敌弹速度（2048 不受影响）；
  简单 = 速度 x0.8，困难 = 速度 x1.25。
* 每个游戏的最高分存在**数据 Flash**（0x00070000 起，与程序区完全分开），
  记录里带 magic + 版本 + CRC16：
  * 只有在**真的破纪录**时才写一次 Flash，不是每帧写；
  * 读出来 CRC 不对（或者版本对不上）就当"没有纪录"，绝不会因为掉电写了一半而读出乱码；
  * 写的时候会关中断，写完恢复；
  * 纪录槽位固定预留 8 个（`GS_BEST_SLOTS`），**往后加游戏不用改记录长度、不用升版本**；
    只有"已有编号的含义变了"（删游戏 / 重排）才必须把 `GS_VERSION` +1；
* 主菜单里选中某个游戏时会显示它的最高分，成绩页也会显示"新纪录"；
  雷霆战机的标题页也会显示自己的最高分。

## 五、中文字库

代码里**不出现中文字符串字面量**（工程是 GBK、编译器按 UTF-8 解会乱），
统一用 `GTXT_xxx` 编号 + `Game_DrawText()`。

加字/改字：

1. 编辑 `font_texts.txt`（GBK 编码），加一行 `GTXT_XXX=新文字`；
2. PC 上跑 `powershell -ExecutionPolicy Bypass -File font_gen.ps1`；
3. 把重新生成的 `game_font16.*`、`game_text.*` 覆盖回工程；
4. 打开 `font_preview.png` 看一眼，确认新字没缺笔画。

> 删字时顺序会整体前移（编号跟着变），但只要所有 `.c` 都重新编译就没问题——
> 代码里只写 `GTXT_xxx` 名字，不写数字。

## 六、内存 / Flash 预算

### 雷霆战机对象池（SRAM）

| 对象 | 数量 | 每个 | 小计 |
|------|------|------|------|
| 玩家 | 1 | 20 B | 20 B |
| 玩家子弹 | 12 | 20 B | 240 B |
| 敌机 | 10 | 20 B | 200 B |
| 敌弹 | 16 | 20 B | 320 B |
| 爆炸特效 | 8 | 20 B | 160 B |
| Boss | 1 | 20 B | 20 B |
| **合计** | **48** | | **960 B** |

* 一个对象 = 位置 `(x,y)` + 速度 `(vx,vy)` + 上次画的屏幕位置 `(px,py)` 共 6 个 int16
  `+ 尺寸(w,h) + 血量(hp) + 类型(kind) + 存活(alive) + 已画(drawn)` 共 6 个 uint8
  `+ 计时(timer)` 1 个 uint16 = **20 字节**；
* `game_thunder.c` 里有一条**编译期断言** `sizeof(ThdObj_t) == 20`，
  以后谁把结构改大了会直接编译报错，提醒同步更新这张表；
* 加上状态变量，`game_thunder.o` 实测 `.bss = 1003 字节`（RISC-V 工具链 `size` 跑出来的真数）。
  **对象池 + 状态合计不到 1.1KB，满足"总 SRAM < 1.5KB"的要求。**

### Flash

| 项目 | 大小 |
|------|------|
| `game_thunder.o` 的 `.text` | 7019 B |
| 字库增量（90 → 96 字，多了 雷/霆/战/机/等/级） | +192 B |
| 菜单 + 主程序增量 | 约 +200 B |
| **雷霆战机带来的总增量** | **约 7.4 KB** |

整机（游戏机 main + 全部游戏 + 硬件驱动 + WCH 库）实测：**FLASH 28768 B / 448 KB（6.3%）**，
RAM 5068 B / 26 KB。文档给的是"程序 + 字库预留 20KB 以内"，实际 7.4KB，余量很大。

> 这个数是**不开 BLE 广告**的游戏机固件。工程里另一条主线（键盘模式）要跑 BLE 协议栈，
> RAM 会紧张得多。

## 八、几个说明

* `G2048_TEST_HOOKS` / `THD_TEST_HOOKS` 里的函数（摆棋盘、摆敌机、指定 Boss、读内部状态）
  只在主机自测时编译进来，**真机固件里没有**；
* 音效接口 `Game_Sound(freq, ms)` 已经接到雷霆战机上（开火 / 爆炸 / 受伤 / 炸弹 / Boss 警报），
  但它本身还是空函数，以后接无源蜂鸣器只改这一个函数，游戏代码一行都不用动；
* 屏刷新全部是"局部重绘"（只擦变化的地方），不做全屏重画，所以不会闪；
  雷霆战机每帧只擦/画真正动过的那几十个小矩形。背景的静态星图**不滚动**，
  擦除时会把落在擦除框里的星点补画回来，所以不会留下一条条"空道"；
* 位置和速度全部是整数定点（1/16 像素），板上没有 FPU，一行浮点都没有；
* 雷霆战机里没有 GPIO 引脚号、也没有 `malloc`——输入走 `Game_KeyDown()` / 按键事件，
  对象全在静态数组里。

## 九、文档里对不上的地方（已按需求实现）

`雷霆战机横屏打飞机开发文档.md` 有两处自相矛盾，实现时按下面的方式定了：

1. **Boss 什么时候出现**：文档 6.4 写"每 30 秒一波、**第 3 波**出现 Boss"（= 60s），
   第十章的表格却写"**120s+** Boss 出现"。两处整整差了一倍。
   → 按 6.4 + 需求走 **第 3 波（60s）**，并把四种敌机压缩到第 3 波之前全部露面，
   否则按第十章的节奏高速机永远没机会出现。想改回 120s，把 `game_thunder.c` 里的
   `THD_BOSS_WAVE` 从 `3` 改成 `5` 就行，一行的事。
2. **玩家碰撞盒缩小多少**：文档 7.3 写"缩小 2px"，十四章第 6 条写"小 1~2px"。
   → 按"合计比图形小 2 像素"实现（`THD_HIT_INSET = 1`，左右上下各内缩 1px）。
3. 另外文档 §3.3 建议的 `key_is_pressed()` 抽象层，在本工程里等价的就是公共层的
   `Game_KeyDown()`；游戏代码里**没有**出现任何 GPIO 引脚号，这一条是遵守的。
