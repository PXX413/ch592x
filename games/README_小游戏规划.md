## 二、可用资源盘点

| 项目 | 情况 |
|------|------|

## 三、输入映射（关键约定）

### 统一按键事件
`game_port` 把"9 个键盘键 + 编码器旋转 + 编码器按键"统一成一种事件，
带**短按 / 长按 / 连发**，游戏里只处理事件，不碰 GPIO。
（雷霆战机里"按住持续移动 / 连发"用的是实时查询接口 `Game_KeyDown()`，
这正是文档 §3.3 说的那层按键抽象，等价于 `key_is_pressed()`。）

### 方向键用 WASD 手感

```
   K1  K2  K3              上 = K5
   K4  K5  K6      ==>     左 = K4     右 = K6
   K7  K8  K9              下 = K8
```

即中间一行是左右，中间键是上，下面中间是下 —— 和电脑上的 WASD 位置一致，手感最好。

### 各游戏键位

| 游戏 | 键位 |
|------|------|
| 2048 | K5=上、K8=下、K4=左、K6=右、K7=撤销、K9=退出 |
| 跑酷 | K5=跳、编码器按键=二段跳、K8=滑铲、K7=暂停、K9=退出 |
| 雷霆战机 | K5=上飞、K8=下飞、K4=按住连发、编码器按键=炸弹、K7=暂停、K9=退出 |
| 菜单 | 编码器旋转=上下选、编码器按键/K5=确定、K1/K3=难度、K7=音效、K9=返回 |

> 界面里会画一条"按键提示条"（例如 `K4< K6> K5转 K8v`），不用背键位。

## 四、游戏设计要点

> **方向：四个游戏（2048 / 跑酷 / 雷霆 / 选单）现在**全部走横屏 240x135**。
> 2048 原本是竖屏 135x240，已改成横屏：布局重排成“左棋盘 + 右信息面板”。
> `GAME_PORTRAIT` 枚举仍保留（公共层支持），但没有游戏再用它。

### 1. 2048（横屏 240x135）
* 4x4 棋盘，格子 30px + 间隔 3px = 132px 宽（屏宽 135），顶部留 60px 放分数条
* **横屏 240x135**：左边 x=4..105 放 4x4 棋盘（每格 24px、间隔 2px，
  本体 102px，竖向居中在 y=7..108）；右边 x=114..239 是分数/最高分面板
* 底部 y=117..134 是按键提示条
* 数值 2~2048 用不同底色；数字字号按位数选 1x/2x
* 标准规则：同值合并（一次移动每块只合并一次）、每次移动后在空格生成 2（90%）或 4（10%）
* 结束判定：无空格且四个方向都无法合并；可"撤销一步"（存上一次棋盘快照 16 个 uint16 = 32B）
* 达到 2048 显示"WIN"，可以继续玩

### 2. 跑酷（横屏 240x135）
* 横版卷轴：地面固定，背景滚动，玩家小方块/小人靠重力跳跃，障碍物从左往右移动
* 三种障碍：矮的（跳）、高的（必须二段跳或早跳）、悬空（滑铲通过）
* 分数 = 距离；速度随时间线性提升；碰撞判定用矩形重叠
* 操作：跳（可变高度：松手上升变慢）、滑铲（限时）、二段跳

### 3. 雷霆战机（横屏 240x135）

#### 3.1 布局
```
y=0  .. 17    顶部 HUD：生命条(左) / 炸弹数 / 等级 / 分数(右)
y=18 .. 134   战场（对象只在这里活动，所有绘图自动裁剪到这个矩形）
```

#### 3.2 状态机
```
BOOT(0.5s 标题) --> MENU(按开始) --> PLAYING <--> PAUSED --> GAMEOVER / WIN
```
* `PLAYING` 被 K7 打断进 `PAUSED`；掉光命进 `GAMEOVER`；打掉 Boss 进 `WIN`
* K9 在任何页面都能退出回主菜单；`GAMEOVER` / `WIN` 下按 K5 或编码器按键重开

#### 3.3 对象池（静态数组，不用 malloc）
| 对象 | 数量 | 每个 | 小计 |
|------|------|------|------|
| 玩家 | 1 | 20 B | 20 B |
| 玩家子弹 | 12 | 20 B | 240 B |
| 敌机 | 10 | 20 B | 200 B |
| 敌弹 | 16 | 20 B | 320 B |
| 爆炸特效 | 8 | 20 B | 160 B |
| Boss | 1 | 20 B | 20 B |
| **合计** | **48** | | **960 B** |

对象结构（正好 20 字节，`game_thunder.c` 里有编译期断言守着）：
```c
typedef struct {
    int16_t  x, y;      /* 位置：1/16 像素（定点，板上没 FPU） */
    int16_t  vx, vy;    /* 速度：1/16 像素 / 20ms */
    int16_t  px, py;    /* 上一次画到屏幕上的像素位置（脏矩形擦除用） */
    uint8_t  w, h;      /* 尺寸，对象一生不变 */
    uint8_t  hp;
    uint8_t  kind;
    uint8_t  alive;
    uint8_t  drawn;
    uint16_t timer;     /* 毫秒计时：开火间隔 / 爆炸剩余时间 */
} ThdObj_t;
```

#### 3.4 每帧（20ms）顺序
```
1 玩家移动 + 连发   2 玩家子弹   3 敌机（移动 + 射击机开火）
4 敌弹   5 Boss（进场 / 摆动 / 三向炮）   6 按难度生成新敌机
7 AABB 碰撞（子弹x敌机、子弹xBoss、玩家x敌机/敌弹/Boss）   8 爆炸计时
```

#### 3.5 碰撞
* 全部 AABB 矩形相交；
* **玩家碰撞盒比图形小 2 像素**（左右上下各内缩 1px，`THD_HIT_INSET = 1`）；
* 子弹用完整尺寸。

#### 3.6 难度曲线
| 波次 | 时间 | 敌机速度 | 生成间隔 | 出现的敌机 |
|------|------|---------|---------|-----------|
| 1 | 0~30s | 1.0x | 1000ms | 小飞机（1血/100分） |
| 2 | 30~60s | 1.2x | 800ms | + 斜飞（1血/150分） |
| 3 | 60~90s | 1.5x | 600ms | + 射击机（2血/300分，会还击）+ 高速机（1血/200分），**Boss 登场** |
| 4 | 90~120s | 1.8x | 500ms | 全部 |
| 5 | 120s+ | 2.0x | 400ms | 全部 |

* Boss：50 血、进场后停在 x=184 上下摆动、每 900ms 打一次三向炮、5000 分，击落即通关；
* Boss 战期间普通敌机照出，但生成间隔放慢；
* 主菜单的难度设置会把上面的速度乘 0.8（简单）/ 1.0（普通）/ 1.25（困难）。

#### 3.7 渲染（脏矩形）
* 每个对象记住"上一次画在屏幕上的像素矩形"，每帧先擦旧矩形再画新矩形；
* 背景的静态星图不滚动；擦除时会把落在擦除框里的星点补画回来，避免留下"空道"；
* HUD 只在内容变化（分数 / 命 / 炸弹 / 等级 / Boss 警报闪烁）时才重画那一条 240x18；
* 菜单页、暂停页、结束页是静态画面，只在进入那一刻整屏画一次。

## 五、统一游戏框架

每个游戏对外只暴露这几个函数，主程序像一个"游戏机"：

```
void     XXX_Enter(void);                 进入：清屏、初始化状态、画静态背景
void     XXX_Update(uint16_t dt_ms);      逻辑推进（固定 20ms 调用）
void     XXX_Draw(void);                  只重绘"变脏"的区域
bool     XXX_HandleKey(GameKeyEvent_t e); 处理一个按键事件（返回是否要回菜单）
uint32_t XXX_GetScore(void);              取分数（结束时给菜单）
bool     XXX_IsOver(void);                这一局结束了没有
bool     XXX_IsPaused(void);              是否暂停中
```

雷霆战机另外多几个只读接口：`THD_IsWin()` `THD_GetLives()` `THD_GetBombs()`
`THD_GetLevel()` `THD_GetState()` `THD_BossAlive()` `THD_GetBossHp()`，都是给测试和以后扩展用的。

`game_port` 提供：

| 接口 | 说明 |
|------|------|
| `Game_Init(orient)` | 初始化键盘 + 编码器 + 屏，设定横/竖屏 |
| `Game_Task()` | 放主循环：扫键、扫编码器、推进 1ms 节拍 |
| `Game_PollEvent(&ev)` | 取一个按键事件（短按/长按/连发/编码器 +/-/按下） |
| `Game_KeyDown(k)` / `Game_KeyHeldMs(k)` | 现在是否按着 / 按住多久（"按住持续动作"用这个） |
| `Game_Millis()` | 毫秒计数 |
| `Game_Rand()/Game_RandRange(n)` | 伪随机数（xorshift32） |
| `Game_DrawNumber(x, y, num, scale, fg, bg)` | 放大数字 |
| `Game_DrawNumberRight(x_right, y, ...)` | 右对齐数字（分数用） |
| `Game_DrawHintBar(GTXT_xxx, fg, bg)` | 底部按键提示条 |
| `Game_DrawTextCenter(y, GTXT_xxx, fg, bg)` | 居中文字（游戏结束、暂停） |
| `Game_Sound(freq_hz, ms)` | 音效预留接口（现在是空函数） |

**防闪烁原则**：不做整屏清屏重画，只重绘变化的格子/区域；
屏上每个"格子"用 `TFT_FillRect` 一次刷完，避免看到逐像素扫描。

## 六、内存 / 性能预算（实测）

| 游戏 | 状态数据 | 备注 |
|------|---------|------|
| 2048 | 棋盘 16x2B = 32B + 撤销快照 32B ≈ 70B | 两次遍历合并 |
| 跑酷 | 障碍物 6 个 x 8B = 48B ≈ 100B | 矩形碰撞 |
| 雷霆战机 | 对象池 48 x 20B = 960B + 状态 ≈ **1003B**（`size` 实测 `.bss`） | 静态数组，无 malloc |
| 框架 | 按键队列、提示条 ≈ 50B | — |

全部游戏加起来也不到 1.2KB，SRAM 完全没压力。**瓶颈只在屏刷新**：
局部重绘一次几十~几百像素，软 SPI 也能轻松跑 30~50Hz。

整机（游戏机 main + 全部游戏 + 硬件驱动 + WCH 库）实测：
**FLASH 28768 B / 448 KB（6.3%），RAM 5068 B / 26 KB（19.0%）**。

## 七、已确认的方案

输入端 **3x3 键盘 + 旋转编码器**；屏幕 **全部横屏 240x135**；
最高分 **存 Flash 掉电保留**；界面 **中文（精简字库）**；
音效走预留接口（现在是空函数，接无源蜂鸣器时只改 `Game_Sound()` 一个函数）。

### 7.1 最高分存 Flash 的做法
* 用 SDK 自带的数据 Flash 接口：`EEPROM_READ / EEPROM_WRITE / EEPROM_ERASE`
  （见 `ISP592.h`；数据 Flash 区从 0x00070000 开始，最多 32KB，写页 256B、擦块 4KB）。
  链接脚本里代码只用到前 448K，所以数据区不会被程序覆盖。
* 记录格式：`magic(2B) + 版本(2B) + 8 个纪录槽 x 4B + 难度(1B) + 上次玩的(1B) + 音效(1B) + 保留(1B) + CRC16(2B)`。
  **版本号很重要**：
  * **已有编号的含义变了**（删游戏、重排顺序）→ 必须升版本，旧记录会被判为无效并回到默认值。
    删掉贪吃蛇/俄罗斯方块时就这么干过，版本从 `0x0001` 升到 `0x0002`；
  * **只是往后新增一个编号**（比如这次加 `3 = 雷霆战机`）→ 老编号一个没动，
    8 个纪录槽也够用，**不用升版本，老纪录继续有效**。当前版本仍是 `0x0002`。
* 写入策略：**只在刷新纪录那一刻写一次**（不是每帧写）；写前关中断
  `__risc_v_disable_irq()`，写完恢复；读出来做 CRC 校验，校验失败就当"没有纪录"，
  绝不会因为写了一半而卡死。Flash 擦写寿命 10 万次，按这个用法用不坏。

### 7.2 中文界面（16x16 点阵）
当前字库：**96 个字 = 3072 字节**，字符串表 **57 条**。

| 用途 | 字表 |
|------|------|
| 游戏名 | 跑 酷 雷 霆 战 机 菜 单 |
| 分数/状态 | 分 数 最 高 等 级 时 间 速 度 纪 录 生 命 |
| 流程 | 游 戏 结 束 暂 停 开 始 重 新 胜 利 继 续 退 出 返 回 选 择 新 纪 录 按 任 意 键 |
| 难度 | 难 度 简 单 普 通 困 |
| 提示/操作 | 上 下 左 右 跳 跃 滑 铲 冲 刺 加 速 撤 销 确 定 取 消 是 否 设 置 音 效 按 键 开 关 |
| 蓝牙 | 蓝 牙 设 备 扫 描 中 连 接 已 断 未 找 到 配 对 选 择 键 盘 模 式 游 戏 宿 主 为 |

* 数字和英文继续用现有 5x7 字库放大 2~4 倍（分数用大号字更清楚）。
* 生成方式：PC 上用 .NET GDI+ 从系统字体（宋体）渲染 16x16 点阵，生成
  `game_font16.c`（`const uint8_t` 数组，占 Flash 不占 SRAM），再把生成的点阵
  **反向渲染成 PNG 自查一遍**，确认没有缺笔画、串位、错行。
* 代码里**不写中文字符串字面量**，只用 `GTXT_xxx` 编号，避免 GBK/UTF-8 打架。

### 7.3 音效
`game_port.h` 提供 `Game_Sound(freq_hz, ms)`，现在内部是空函数。
雷霆战机已经按"开火 / 爆炸 / 受伤 / 炸弹 / Boss 警报"五处调用了它，
以后想加蜂鸣器，只改这一个函数，游戏代码一行都不用动。

### 7.4 屏幕方向
`game_port` 提供 `Game_SetOrientation(横屏/竖屏)`，内部调 `TFT_SetRotation()` 并刷新
宽高变量；游戏代码只按自己的逻辑坐标画，不用管旋转。
